# 广莫设计规范

## 1. 产品气质

广莫是帮助用户管理生活，安排学习和推进长期方向的个人 Agent。

界面应平静，清晰，有留白，让用户容易看见当前重要的事情。
避免制造紧迫感，不使用排行榜，连续打卡或惩罚性提醒。

用户始终可以修改，拒绝或暂停 Agent 的建议。

## 2. 图标

### 图标来源与造型

当前原型的功能图标统一使用 Phosphor Icons，不混用其他图标库、Emoji 或单字占位。图标 SVG 和许可证保存在 `design/icons/phosphor/`；原型将 SVG 路径内嵌到页面，保证直接以本地文件打开时也能显示。同一功能使用同一图形的 regular 与 fill 两种官方字重。

保留 Phosphor 官方 256 × 256 `viewBox` 与原始路径比例。侧栏优先选用圆形轮廓、圆角和柔和转折的图形：对话用圆形气泡，项目用四圆点，每周回看用圆形勾选。导航未选中时使用 regular，当前页使用同名 fill；不要手工填充线框或另外绘制实心图标。选中底块只辅助识别。不拉伸、旋转或给图标加装饰性渐变、阴影。

### 尺寸与点击区域

| 位置 | 图形尺寸 | 字重 | 点击区域 |
|---|---:|---:|---:|
| 主导航 | 20 × 20px | 未选中 regular，选中 fill | 最小 44 × 44px |
| 顶栏、附件、历史及连接器工具 | 18 × 18px | regular | 最小 44 × 44px |
| 发送按钮内箭头 | 18 × 18px | regular | 最小 44 × 44px |
| 附属下拉箭头 | 12 × 12px | regular | 随所属按钮共用点击区域 |

导航的可见选中底块为 36 × 36px、圆角 20px，位于 44 × 44px 的点击区域中央。图标和文字之间留 8px。紧凑尺寸也要保证移动端容易点击。

### 状态与语义

- 未选中的线框使用 `--secondary`，悬停和选中实心图标使用 `--text`；当前页另有 `--selected` 底块，悬停用 `--hover`，键盘焦点用 `--focus`。浅色和暗色都按实际背景检查对比度。
- 当前页同时设置 `aria-current="page"`，仅用颜色不能表达当前状态。不可用操作同时设置 `disabled`，降低图标与按钮对比度。
- 有可见文字的按钮将图标标为装饰；纯图标按钮必须提供明确的 `aria-label`。图标本身不单独进入键盘焦点顺序。
- 悬停只改变图标和底块的颜色；不得位移、缩放或改变点击区域尺寸。状态变化不改变图标语义。

### 品牌图标与实现状态

广莫 Logo 使用正式的 `design/guangmo-logo-river.svg`，保持轮廓与比例，不以功能图标或单字代替。深色背景使用浅色反显。

原型侧栏使用 Phosphor 的 regular 与 fill 图形；原型顶栏和工具按钮也使用同一套图标。点击区域仍需按上述尺寸核对。

### 图标的视觉一致性

同组图标应在视觉大小、重心和粗细上保持协调，
不能只依靠相同的宽高判断是否一致。

允许根据图形的内部留白和轮廓做适度的等比缩放，同时保存布局对齐和点击区域稳定。

线框与实心状态切换时，应避免明显的大小跳变。
具体调整以实际界面效果为准，不要求所有图标使用相同缩放比例。

## 视觉基调

- 采用现代、简洁的工作台风格，保留柔和圆角与充足留白。
- 当前原型使用浅色银灰：白色主区、浅灰侧栏、深灰正文与灰色辅助文字，主题色只作为点睛色。
- 主要操作使用黑色按钮；主题色使用高饱和翡翠绿 `#059669`，用于选中图标、焦点、链接和轻量状态；选中背景使用 `#D4F3E5`，悬停背景使用 `#E9F9F2`。
- 所有区域统一使用系统无衬线字体，不使用宋体、水墨晕染或仿纸纹理。
- 减少独立卡片和背景块，用间距与轻量分隔建立层次。

### 布局与入口

- 侧栏固定为 52px 图标窄栏，不提供展开／收起操作。侧栏不展示 Logo，顶部直接显示功能入口，底部保留连接器与账户。
- 会话列表顶部提供无底色的「新建会话」入口，使用 Phosphor `plus-circle` 的 regular 圆形加号图标并遵循工具图标尺寸，文字与图标使用正文色 `--text`，默认无底色，悬停时使用 `--hover` 背景，下方按「置顶」「项目」「最近」顺序分组。新建入口复用工作区的新建逻辑，有未发送草稿时先确认。点击侧栏“对话”图标，在其右侧显示会话列表；宽屏与工作区并排，窄屏使用浮层。图标栏保持固定宽度。对话页顶部保留新建入口和打开同一列表的历史入口。
- 主区域与侧栏同色，外围使用浅灰底；面板带轻微投影，选中项用轻量浅灰底。
- 侧栏与主区为两个独立圆角面板，均使用 20px 圆角，桌面外距 6px，窄屏外距 4px，面板间距为 4px。
- 对话区最大宽度 736px，内容页最大宽度 880px；桌面内容左右内边距 20px。
- 顶部栏高度 52px；对话记录独立滚动，输入区留在底部。

### 间距与留白

使用 4px 基础尺度。组件内部与区域之间根据层级选用以下值，不随意添加相近数值。

| 尺度 | 用途 |
|---|---|
| 4px | 紧密关联控件、列表行内留白 |
| 8px | 图标与文字、列表分组、相邻操作 |
| 12px | 常规按钮内边距、常规容器内边距、文字组间距 |
| 16px | 表单与面板常规内边距、相邻内容组 |
| 24px | 较大区块间距，按需使用 |
| 32px | 大区块留白，按需使用 |
| 48px | 大区块之间的留白，按需使用 |
| 64px | 特殊展示场景，常规工作台不默认使用 |

- 采用紧凑的工作台密度，先减少重复留白，再按内容关系分组；不靠缩小文字压缩界面。同一组件内部使用同一尺度，密切相关内容距离小，不同分组距离大。会话行在桌面使用紧凑行高，触摸设备保留足够点击面积。会话分类标题与条目文字左对齐；分类标题使用辅助色 `--muted` 和适中的字重，条目使用正文色 `--text`，明确区分标题与内容。不使用额外缩进、分隔线或大段空白分组。
- 图标栏中交互区域为 44 × 44px，导航项不加额外间隔，底部辅助入口与账户间距 4px；窄栏左右各留 4px。选中与悬停底块为 36 × 36px、圆角 20px，点击区域仍为 44 × 44px。
- 面板外距独立配置，不用于组件内部。
- 间距通过 CSS 的 `--space-*` 变量引用；布局使用 `--frame-gap`、`--page-inset`、`--header-height` 等语义变量。

### 圆角

圆角矩形统一采用接近苹果连续曲率的平滑转角，让直边与转角自然衔接。面板、输入框、按钮、浮层、消息气泡及导航状态底块使用同一种曲线风格；圆角大小仍按组件层级调整，不要求所有组件使用同一半径。完整圆形和胶囊形保留其形状，品牌 Logo 与图标原始路径不受此规则影响。

Web 通过 `--corner-shape` 统一配置 `corner-shape: squircle`，同时覆盖伪元素。它是网页端的风格近似，不代表与苹果原生曲线完全一致。原型中的头像、发送按钮和胶囊入口显式使用 `round`；正式应用中的圆形或胶囊组件用 `data-corner="round"` 标记。使用 `@supports` 做渐进增强，未支持的浏览器保留普通 `border-radius`；验收时需确认目标浏览器的实际效果。参考：[MDN corner-shape](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/corner-shape)。

| 类型 | 圆角 |
|---|---|
| 小按钮、工具入口 | 20px |
| 导航选中态、常规浮层 | 16px |
| 侧栏与主区面板 | 20px |
| 输入框、消息气泡、内容分组 | 24px |
| 发送按钮、头像 | 圆形 |
| 快捷文字入口 | 胶囊形，仅悬停显示背景 |

### 文字与层级

- 系统无衬线字体；主标题 30px，内容页标题 28px，区块标题 18–20px。
- 正文 14–15px；导航 13px；辅助文字 11–12px。
- 主要文字深灰，次要文字中灰，辅助文字浅灰。黑色主按钮是最强操作强调。
- 内容分组使用低对比度浅灰背景，不堆叠嵌套面板；浮层使用白底和轻微投影，不使用黑色边框。

### 响应式

- 1000px 以下，内容左右内边距缩为 16px。
- 640px 以下，外距与面板间距 4px，内容内边距 12px，顶部栏高度 48px，图标栏宽 52px。
- 移动端输入框文字至少 16px，输入区底部包含安全区留白。
- 对话区高度使用顶部栏和外距变量计算，避免切换侧栏或屏幕尺寸后出现额外滚动。

### 维护

调整对应组件规则，不追加整套主题覆盖。修改尺寸时同步核对默认、聚焦、展开和移动端状态，并更新本规范。

图标语义、尺寸与状态以第 2 节为准。

### 主题色

- 主色：`#059669`
- Hover：`#047857`
- 选中背景：`#D4F3E5`
- 浅色背景：`#E9F9F2`
- 主色只用于交互状态，不给大面积容器或正文染色。

### 色彩使用原则

- 结构色以白色、黑色和中性灰为主：白色用于画布与浮层，黑色用于主要文字和主要操作，灰色用于层级、分隔和辅助信息。
- 主题色不承担大面积背景、主要按钮或内容卡片的填充，只用于需要用户注意的交互状态。
- 同一页面最多使用一种主题色；不要为导航项目分别指定颜色。

### 暗色主题预览

- 画布：`#24252A`；侧栏：`#202125`；页面外层：`#111216`。
- 主文字：`#E8E7E3`；辅助文字：`#A7A7AA`；输入区：`#2D2E33`。
- 品牌主题色仍为墨黑；暗色背景上 Logo 使用浅色反显，保持可见性。
- 主要按钮使用米白底和深色字，选中态使用深灰面，不引入额外彩色强调。

### 国风水墨参考的取舍

- 借鉴水墨网站的墨黑、暖白、留白和细线分隔，不直接加入大幅山水、宣纸纹理或装饰性印章。
- 现代工作台结构保持不变；东方感集中在 Logo、标题字距、暖白底色和轻量笔墨式分组线。
- 主题色继续作为点睛色，不覆盖内容区；主要按钮和正文使用墨黑。

### 主题切换

- 顶部提供亮色 / 暗色切换。
- 亮色：白色内容区、浅银灰侧栏、墨黑文字。
- 暗色：`#24252A` 内容区、`#202125` 侧栏、米白文字。
- 主题色和 Logo 规则在两种模式保持一致；暗色模式只做对比度反转，不引入新的彩色体系。
- 用户选择保存在本地，刷新后保持当前主题。

## 原型收尾基准

当前以页面实际实现为准：冷白亮色与石墨暗色共用语义颜色变量，不再叠加历史彩色方案。Logo 为墨黑，暗色反显；所有交互使用中性黑白灰。顶部提供主题切换并保存选择。侧栏不放新建对话或对话历史。实现边界和待验收项见 `prototype/README.md`。

## Web 颜色使用与验收（现行）

广莫 Web 的浅色方案采用冷白主区与浅灰侧栏。前文的翡翠绿与暖白是历史方案。下表已同步到 [主题变量](../apps/web/src/app/tokens.css) 和交互原型。组件按用途引用变量，例如侧栏使用 `var(--sidebar)`。

| 用途 | 语义变量 | 浅色目标值 |
|---|---|---|
| 页面外层 | `--outer` | `#F5F5F5` |
| 侧栏 | `--sidebar` | `#EBEBEB` |
| 主内容区与浮层 | `--surface` | `#FFFFFF` |
| 输入框 | `--input` | `#FFFFFF` |
| 次级内容背景 | `--panel` | `#FAFAFA` |
| 主文字 | `--text` | `#202020` |
| 次要文字 | `--secondary` | `#666666` |
| 辅助文字 | `--muted` | `#737373` |
| 分隔线 | `--line` | `#E8E8E8` |
| 输入框边框 | `--input-line` | `#D9D9D9` |
| 悬停背景 | `--hover` | `#EDEDED` |
| 选中背景 | `--selected` | `#E5E5E5` |
| 主要按钮 | `--strong` | `#202020` |
| 按钮文字 | `--on-strong` | `#FFFFFF` |

暗色值仍以主题变量为准。本次选择只确定浅色方案。

- **文字**　在实际背景上检查对比度，普通文字至少 4.5:1，大号文字至少 3:1。辅助说明、时间和输入框占位文字也按实际字号检查。[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- **图标与焦点**　识别可用控件或其状态所必需的图标、边界或自定义焦点指示，与相邻颜色至少达到 3:1。纯装饰分隔线可以更淡。[WCAG 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- **状态**　选中、悬停和键盘焦点分别使用 `--selected`、`--hover` 和 `--focus`。错误提示应写出原因，让用户在无法分辨颜色时也能理解发生了什么。[WCAG 颜色的使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)
- **验收**　在亮色和暗色下分别检查正文、辅助文字和控件。打开一个页面，把指针移到另一导航项，再按 Tab，确认当前页和键盘焦点均可辨认。若使用半透明浮层，在浅色和深色内容上分别检查浮层文字。[Apple 颜色指南](https://developer.apple.com/design/human-interface-guidelines/color)
- **暗色浮层** 菜单等浮层叠在主内容区上时，优先使用比主背景略亮的面板色。验收时，把浮层放在实际页面上，检查能否看清它的边界，并判断哪些操作属于它。
